# 0004. Terrain Processing & Deterministic Multi-Hazard Engine

**Status:** Accepted  
**Date:** 2026-10-08  
**Tag:** `[ENGINEERING DECISION]`

---

## Context
Per PRD §8 (FR-H1–FR-H5), §10, and §11, Surakshit Basti requires a pure, deterministic multi-hazard assessment engine to compute composite hazard scores for terrain cells:
1. Landslide hazard from slope, aspect, curvature, drainage proximity, road proximity, land cover, and historical events.
2. Flood hazard from Height Above Nearest Drainage (HAND), flow accumulation, distance to river, wetness index, and land cover.
3. Flash-flood / cloudburst dynamic trigger multiplier based on short-duration rainfall spikes.
4. Coastal erosion class (optional static layer).
5. Combined multi-hazard formula: $H = 1 - \prod_{k} (1 - H_k)$ with Red ($\ge 0.70$), Amber ($0.40 - 0.70$), and Green ($< 0.40$) classification.
6. Per-factor explainable contributions.

## Decision
1. **Engine Purity & Determinism**:
   - `backend/app/engines/hazard_engine.py` is implemented as pure Python functions without database, clock, or network dependencies. All inputs and outputs are typed dataclasses/Pydantic schemas.
2. **Formula Specifications**:
   - **Landslide Baseline**: $H_{ls} = \sum w_i \cdot f_i(x)$ with normalised factor functions $f_i \in [0, 1]$ (steeper slope, convergent curvature, proximity to drainage/roads, barren/degraded land cover, past landslide density).
   - **Flood Baseline**: $H_{fl} = \sum w_j \cdot g_j(x)$ (lower HAND, higher flow accumulation/wetness, river proximity).
   - **Dynamic Trigger**: Scaled by rainfall multiplier $M_{rain} = \min(2.0, \max(1.0, R / R_{alert}))$.
   - **Combined Hazard**: $H = 1 - (1 - H_{ls})(1 - H_{fl})(1 - H_{co})(1 - H_{ff})$, mathematically strictly bounded in $[0.0, 1.0]$.
   - **Class Assignment**: Red for $H \ge T_{red}$ (default 0.70), Amber for $T_{amber} \le H < T_{red}$ (default 0.40), Green for $H < T_{amber}$.
3. **Terrain Factor Computation**:
   - Implemented using pure NumPy 2 and SciPy vectorised convolution/gradient filters for slope (degrees), aspect, curvature, flow accumulation, TWI ($\ln(a / \tan \beta)$), and HAND.
4. **PostGIS Integration**:
   - `backend/app/services/hazard_service.py` handles database loading of cells with geometries in EPSG:4326.
   - `cells.structural_hazard` persists the static terrain/landcover score separately from `cells.combined_hazard`, which can include rainfall-triggered dynamic expansion.
5. **Configuration Compatibility**:
   - District YAML factor names such as `distance_to_drainage`, `distance_to_roads`, `historical_events`, `flow_accumulation`, and `wetness_index` are canonicalised inside the engine and renormalised before scoring.
6. **Demo Cell Provenance**:
   - Until processed raster layers are connected to the loader, the deterministic bbox-grid cells generated by `hazard_service.generate_district_cell_grid()` are explicitly labelled `DEMO_SYNTHETIC`.
